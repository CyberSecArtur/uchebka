# Спецификация API StockDesk

API запускается на loopback. Защищённые запросы передают `Authorization: Bearer <token>`. В таблице А — администратор, М — менеджер, К — кладовщик.

| Метод и путь | Доступ | Назначение |
| --- | --- | --- |
| GET `/health` | Любой | Готовность сервера. |
| POST `/api/login` | Любой | Вход по `login` и `password`, выдача токена и роли. |
| GET `/api/customers` | А, М | Покупатели с адресами. |
| POST `/api/customers` | А, М | Добавление покупателя, поля `name`, `address`. |
| POST `/api/customers/import` | А, М | Импорт CSV в теле запроса. |
| GET `/api/users` | А | Список сотрудников. |
| POST `/api/users` | А | Создание сотрудника, поля `login`, `password`, `role`. |
| GET `/api/workers` | А, М | Список кладовщиков для назначения. |
| GET `/api/orders` | А, М, К | Заявки, для К только назначенные ему. |
| POST `/api/orders` | А, М | Новая заявка, поля `customerId`, `description`. |
| PATCH `/api/orders/{id}` | А, М, К | Смена статуса, поля `status`, `warehouseWorkerId`, `price`, `revision`. |
| GET `/api/statistics` | А, М, К | Сводка по доступным заявкам. |
| GET `/api/export/{format}` | А | Выгрузка в CSV, JSON или XML. |

Статусы в JSON кодируются числами от 0 до 4: создана, комплектуется, собрана, отгружена, отменена. Пример запроса смены статуса: `PATCH /api/orders/17` с телом `{"status":1,"warehouseWorkerId":3,"price":null,"revision":0}`. Успешное изменение возвращает 204. Без действующего кладовщика сервер возвращает 400 и `{"message":"Выберите действующего кладовщика."}`.

| Код | Причина |
| --- | --- |
| 400 | Ошибка данных или перехода. |
| 401 | Неверные данные входа или отсутствует действительный токен. |
| 403 | Роль не может выполнить действие. |
| 404 | Заявка отсутствует либо назначена другому кладовщику. |
| 409 | Устаревшая версия заявки или конфликт при сохранении. |
| 429 | Лимит запросов входа, 15 попыток в минуту. |
| 500 | Серверная ошибка. Подробности остаются в журнале. |
